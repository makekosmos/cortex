# update-docs — держать AGENTS.md в синке с кодом

## Когда срабатывать

Скилл запускается на фразы:

- "обнови документацию", "обнови доки", "update docs", "sync docs"
- "запушь", "push", "закоммить и запушь" — **перед** git push сверяем доки с кодом
- "приведи AGENTS.md в актуальное состояние"
- "что из документации устарело?"

Если пользователь просит только `git commit` без push — тоже делай quick-scan: меняется ли поведение, задокументированное в AGENTS.md? Если да — обнови. Если нет — молча коммить.

## Принципы

AGENTS.md — это **guide для будущих AI-сессий**, не README для людей. В нём должны жить:

1. **Инварианты / правила** — "MUST", "NEVER", "только так". Например: "UUID MUST be lowercase", "beacon dedup обязателен", "имя устройства = host name".
2. **Карта файлов** — какие файлы за что отвечают (таблица `Файл | Роль`).
3. **Gotchas и past incidents** — "не делай X, потому что Y упало в прошлом" с кратким "Why".
4. **Специфичная конфигурация** — порты, форматы, протоколы.

**Не нужно класть в AGENTS.md:**

- то, что очевидно из `git log` / `git blame`
- временный статус работ ("сейчас чинится баг X")
- полный API reference (это код читает сам)
- changelog прошлых фиксов без извлечённого правила

## Workflow

### 1. Разведка — что реально поменялось

```bash
git status
git diff HEAD              # unstaged + staged
git log --oneline -20      # последние коммиты в сессии
```

Если сессия была длинной — прочитай diff полностью по каждому файлу, чтобы понять **смысл** изменения, не только строки.

### 2. Матчинг — какой AGENTS.md покрывает изменённые файлы

Правило локальности (из user memory "TECHDEBT locality"): **AGENTS.md живёт рядом с приложением**. Для изменения в `apps/delphi/ts/electron/foo.ts` релевантен:

- `apps/delphi/AGENTS.md` — общий для Delphi
- может быть `apps/delphi/ts/AGENTS.md` если существует

Для `packages/arksync/*` — `packages/arksync/AGENTS.md` (если есть) или родительский.
Корневой `/AGENTS.md` — только если изменение архитектурного уровня (monorepo-wide, новое приложение, смена стека).

Собери список: `{ AGENTS.md file → список code changes которые его касаются }`.

### 3. Для каждого затронутого AGENTS.md

Прочитай текущее содержимое **полностью** (не отрывками). Найди секции, которые описывают изменённый код. Для каждого изменения реши:

| Тип изменения | Действие в AGENTS.md |
|---------------|----------------------|
| Новый инвариант / правило | Добавь в раздел "правила" / "invariants" / "gotchas" |
| Новый файл с ролью | Добавь строку в таблицу "Ключевые файлы" |
| Переименование файла | Обнови ссылки на старое имя |
| Удалён файл | Удали строку из таблицы (и все ссылки) |
| Поменялся протокол / формат | Обнови описание протокола |
| Исправлен баг без нового правила | Обычно **ничего не делать** — фикс в коде, контекст в коммите |
| Архитектурный рефакторинг | Перепиши затронутый раздел |

**Писать кратко.** Один инвариант = одно предложение + опционально "Why:" одной строкой. Таблицы предпочтительнее прозы.

### 4. Проверка

После правок:

- Прогони `git diff <AGENTS.md>` — сам убедись, что изменения осмысленные, а не косметика
- Нет ли дубликатов между секциями (правило описано дважды)?
- Нет ли ссылок на несуществующие файлы? Проверь через `Glob` / `Read`
- Корневой `AGENTS.md` не раздут до >200 строк? Если да — вынеси в `@path` imports или `.agents/rules/*.md` (см. repo-task-proof-loop блок в корневом AGENTS.md)

### 5. Коммит

Если скилл вызван из контекста "push" / "commit" — после обновления доков:

1. Покажи пользователю **короткий summary**: какие AGENTS.md поменялись и почему
2. Дождись `git commit` / push от пользователя. **НЕ** коммить автоматически без явной команды (правило из корневого Claude Code: "NEVER commit changes unless the user explicitly asks")

Если пользователь уже явно сказал "запушь" — можно коммитить и пушить сразу после обновления доков, включив их в тот же или отдельный коммит (выбор по размеру: маленькое обновление — один коммит с кодом, большое — отдельный `docs:` коммит).

## Частые ошибки

- **Переписать весь AGENTS.md заново** — нет, трогай только затронутые секции
- **Добавить changelog** — нет, это `git log`'овое
- **Описать то, что ещё только планируется** — в доках только то, что в коде СЕЙЧАС
- **Скопировать комменты из кода дословно** — резюмируй правило одной строкой
- **Забыть про дочерние AGENTS.md** — одна фича может затрагивать `apps/delphi/AGENTS.md` И `apps/delphi/kotlin/AGENTS.md`
- **Добавить в docs TODO/FIXME** — это не доки, это таски

## Примеры

**Хорошее обновление** (изменение поведения):

```diff
+ ### Дедуп beacon'ов
+ Receiver держит Map<device_id, SeenPeer>, onPeerDiscovered зовётся только при новом device_id или изменении адресов. TTL 30с. Без дедупа — reconnect-спам каждые 5с.
```

**Плохое обновление** (пересказ коммита):

```diff
+ ### Fix #123
+ Исправлен баг с дубликатами пиров в списке. Теперь getConnectedPeers() использует LinkedHashMap.
```

→ Правильно: одна строка в таблице файлов + одно правило в "инвариантах". Всё.
