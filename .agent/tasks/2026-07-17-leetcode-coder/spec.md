# LeetCode auth, sync and Coder page

## Класс задачи

`FULL_LOOP`: исправление Electron auth-flow, изменение интеграционного sync-flow и новый пользовательский экран, читающий ARK-данные.

## Цель

Сделать LeetCode-интеграцию предсказуемой после интерактивного входа, исключить повторные и бесконечно выглядящие ручные синхронизации и добавить страницу «Кодер» со всей статистикой, которую можно достоверно вычислить из локально импортированных отправок.

## В scope

- Свежая интерактивная LeetCode-сессия без принятия stale cookies.
- Закрытие login BrowserWindow сразу после получения новых auth cookies, до сетевой проверки и ARK-вызова.
- Очистка login BrowserWindow и listeners на success/error/cancel.
- Защита от параллельной синхронизации одного provider.
- Полный первый импорт и инкрементальные последующие импорты с небольшим overlap.
- Локальная страница «Кодер»: сводка, активность, языки/результаты и последние отправки.
- Только чтение данных страницы через preload ARK API.

## Не в scope

- Загрузка исходного кода решений.
- Публичный или официальный LeetCode API — используется существующая личная web-session интеграция.
- Новая ARK schema/table или прямой SQL.
- Релиз/изменение версии.

## Acceptance Criteria

**AC1.** При начале нового входа stale cookies очищаются; после появления `LEETCODE_SESSION` и `csrftoken` login BrowserWindow закрывается до вызова runtime credential verification, а UI получает свежий snapshot без перезапуска Kosmos.

**AC2.** Success, cancellation и error paths очищают cookie/listener polling и не оставляют login BrowserWindow открытым.

**AC3.** Одновременный повторный sync одного provider не ждёт mutex и не запускает второй импорт; он быстро возвращает понятную ошибку «синхронизация уже выполняется».

**AC4.** Первый LeetCode sync загружает всю доступную историю; после успешного sync следующий запрос останавливается после небольшого overlap относительно `lastSuccessAt`, а upsert по external submission id остаётся идемпотентным.

**AC5.** Страница «Кодер» доступна из общего sidebar и показывает по локальным `coding_submission_obj`: всего отправок, принятые попытки, уникально решённые задачи, acceptance rate, серии дней, активность, языки, результаты и последние отправки с runtime/memory.

**AC6.** Страница «Кодер» работает offline после импорта и не блокирует остальную навигацию при отсутствии данных или сети.

**AC7.** Renderer не пишет в SQLite напрямую; ARK write guard, целевые Rust/TS tests, typecheck и production build проходят.

**AC8.** Auth/sync regression покрыт тестами, а страница визуально проверена либо ограничение проверки явно зафиксировано в evidence.
