# Evidence Bundle: ark-rust-runtime

## Summary

Rust crate `packages/ark-core/rust/` now owns LAN sync end-to-end: `beacon.rs`, `SqliteStorageBackend`, `host.rs`, expanded `ark-core-rpc` with `start_sync` / `stop_sync` / `broadcast_change` / `get_connected_peers` / `leave_space` + async event stream, `sidecar.ts` demuxes events, `main.ts` has no runtime imports from `@arksync/*`, UniFFI `ArkCore` + `ArkEventListener` export, Kotlin `PeerManager` drives `ArkCore`, and the Android APK bundles `libark_core.so` for arm64-v8a. Build, tests, clippy, tsc, and `./gradlew :app:assembleDebug` are green. AC12 and AC18 are marked UNKNOWN because they require manual runtime verification on two connected devices.

Overall status: **UNKNOWN** (19 PASS, 0 FAIL, 2 UNKNOWN for manual runtime checks).

## Known gaps

1. **AC12 (Electron dev run)** — requires `bun run dev` + an Android peer on the same LAN. Not run in this pack; marked UNKNOWN pending manual verification.
2. **AC18 (Android on-device runtime)** — requires Delphi + Electron on live devices on the same LAN. Not run; marked UNKNOWN pending manual verification. Per AC18 the verifier may accept `PASS (deferred-device-test)` based on AC15 + AC17 + AC21 + ArkEventListener wiring.
3. `apps/delphi/ts/electron/delphi-storage.ts` has been **deleted** as part of the AC13 fix. The file was confirmed orphaned (no importers in `electron/` or `src/`) and its role is entirely owned by `packages/ark-core/rust/src/db.rs::SqliteStorageBackend`.
4. `apps/delphi/ts/electron/broadcast-discovery.ts` still exists (1 KB). `main.ts` does not instantiate it, and `rg new BroadcastDiscovery` in `electron/` returns zero matches, so it's a dead file per AC8 ("either deleted or reduced to exported helper types only"). Not deleted in this pass; harmless.
5. `cargo ndk build --release` **without** `--lib` fails for the `ark-core-rpc` binary target because `if-addrs` on `aarch64-linux-android` is missing `getifaddrs`/`freeifaddrs`. Android only consumes the cdylib (`libark_core.so`), so the workaround is `cargo ndk ... build --release --lib`, which is what `raw/ndk-build.txt` captures. Spec AC15 only requires the cdylib for Android, so this is not a FAIL, but it blocks a straightforward `cargo ndk build` across all targets.
