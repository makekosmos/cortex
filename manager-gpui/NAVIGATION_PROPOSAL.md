# Предложение структуры Manager

Статус: **согласовано и реализовано в GPUI Manager**. Sidebar содержит восемь
основных страниц. Существующие операции перенесены без изменения их API,
файлов настроек, подтверждений восстановления и значений по умолчанию.
Старые функциональные модули остаются источниками контролов внутри новых
страниц; отдельные маршруты «Движок», «Браузер», «Ключи», «Разработка» удалены.
Regression coverage проверяет их через новые страницы, а не скрытые маршруты.

## Принцип

Разделы называют пользовательскую задачу, а не внутреннюю подсистему Engine.
Основное меню — ежедневные действия; настройки, обслуживание и разработка не
должны занимать одинаковый уровень с приложениями и подключёнными устройствами.
Manager показывает состояние и возможности, возвращённые Engine. Проверки
поддержки автозапуска, резервного копирования и автообновлений принадлежат Engine,
а не условным веткам macOS/Windows в компонентах страниц.

## Предлагаемый sidebar

1. **Работа**: Приложения · Данные · Активность.
2. **Связи**: Девайсы · Интеграции.
3. **Система**: Настройки · Внешний вид · Обновления · О приложении.

«Приложения» открывает установленные приложения; каталог/маркетплейс остаётся
вкладкой внутри этого раздела. «Активность» — более понятное имя нынешнего
«Затреканного времени», без изменения смысла собираемых данных.

## Куда перенести текущее содержимое

| Сейчас | Предложение |
| --- | --- |
| Настройки → автозапуск | Настройки → Общие → Запуск при входе. Объяснить, запускается Engine, UI или оба; переключатель не должен менять это молча. |
| Настройки → резервные копии БД | Данные → Резервные копии: расписание, путь, последняя копия, восстановление и последствия восстановления. |
| Движок → лимиты/воркеры/счётчик использования | Настройки → Система и производительность. Термин Engine — в описании, не отдельный ежедневный раздел. |
| Разработка → тема | Отдельная страница «Внешний вид»: режим, две палитры, акцент, материалы, шрифт и общий стиль приложений. |
| Разработка → FPS и локальные пакеты | Настройки → Дополнительно → Инструменты разработчика; раскрываются явно. |
| Ключи | Интеграции → Доступы и API-ключи, с группировкой по назначению и маскированием секретов. |
| Браузер → сохранение данных сайтов | Настройки → Приватность → Данные сайтов. Отдельная страница нужна только при наличии самостоятельных задач браузера. |
| О приложении | Версия Cortex/Manager, версия и состояние Engine, ссылки и раскрываемая поддержка; без дублирования всех настроек и автоматического журнала. |
| Обновления | Установленная версия, канал, опубликованная новая версия, возможность установки, прогресс и результат проверки. Не смешивать это с «О приложении». |

## Девайсы

Текущий компьютер сверху, связанные ниже, подключение нового устройства внизу.
Название раздела — «Девайсы»; «Синхронизация активна» остаётся описанием функции.
Не угадывать ОС, версию или подключённость удалённого устройства по имени.

## Контракт версии и возможностей

- Product version одинакова в Engine и Manager одного собранного пакета;
  Cargo crate version не считается production-версией.
- Bare Cargo/явный dev отображаются с `(dev)`. В API версия остаётся чистым
  semver, канал передаётся отдельно: отображение не ломает сравнение версий.
- Доступная версия берётся из release feed, а не константы «0.10.3» в UI.
  Равную установленной версию нельзя предлагать как обновление.
- Engine возвращает `canInstall` и причину недоступности. Текущий установщик
  Windows-only: native macOS/Linux не скачивают чужой `.exe`. Публикация новой
  версии продукта и наличие подходящего автоустановщика — разные состояния.
- Следующий этап: единый capability-контракт для автозапуска/бэкапов и описание
  локального устройства из Engine. Это не означает, что весь Manager уже
  избавлен от platform-specific кода (нативный window chrome остаётся в UI).

## Проверки и оставшаяся валидация

- Реализованы названия и группы, переносы и opt-in раскрытие разработчика.
- Общая сетка: ширина 760 px, inset карточки 16 px по горизонтали / 12 px по
  вертикали, gap 12 px, 32 px между смысловыми группами / 12 px внутри,
  24 px между обычными карточками, колонка подписи 180 px, базовые строки 18/16 px,
  одинаковые 32 px поля ввода и кнопки. Иконки занимают общий 32 px слот.
- Автотесты проверяют sidebar, запросы перенесённых контролов, статические
  loading/error cards, совпадение краёв и центров контролов, узкое/широкое окно,
  открытый/закрытый sidebar и раскрытые инструменты разработчика.
- Ручная визуальная проверка всех состояний на Windows/Linux и реальный
  двухустройственный pairing остаются отдельной проверкой; автоматическая
  геометрия не считается заменой такой проверки.
