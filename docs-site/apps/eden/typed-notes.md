# Eden typed notes quick reference

Scope: `components/typed-notes/`, `lib/typedNotes.ts`, system typed objects in `lib/systemTypes.ts`.

- Built-in types include `note_obj`, `book_obj`, `person_obj`, image/game/journal system types.
- `book_obj` stores its title in `Entry.title`; optional `author`, `cover_image`, `isbn`, `page_count`, `language`, `publisher`, `published_date`, and `source_url` live in `header_props_json`; arbitrary personal notes stay in the Markdown body. `cover_image` is an `image` field and the type's `imageFieldId`; `source_url` uses the generic `url` field kind. `language` is a predefined select with Russian labels; imported ISO codes and English/Russian names are normalized before preview/apply (`eng`, `en`, and `English` become `Английский`). The collection is «Книги» with the existing `book` icon and accent fallback.
- Books use the same system-type persistence and ARK write path as other Eden objects; do not add a book-specific RPC or database schema.
- `TypedHeader.vue` renders object header fields from `header_props_json`, `header_layout`, note type schema/ui schema.
- Object header layouts are type-driven and reusable: books place an auto-growing multiline title above the whole object block, then show the shared `BookCover` visual on the left and type/properties on the right; the white metadata button stays below all properties and aligns to the bottom of that block. People keep the centered circular portrait layout; plain notes keep the title-only editor header. `BookCover` derives the dominant image color from its rendered pixels and uses it for the spine overlay; remote images blocked by CORS use the existing protected Eden image-color bridge. A missing book cover is a plain gray `+` placeholder that opens the shared Visuals modal for an HTTP(S) URL or a local image selected through the native Vue dropzone patterned after `sadmann7/file-uploader`; local images are copied into Eden user data and `cover_image` stores only the path. Narrow viewports stack media above details.
- A book page can explicitly import metadata from a public HTTPS page or an ISBN; an ISBN already stored on the book is prefilled. Direct ISBN input calls the dedicated fixed-origin Open Library edition endpoint without an API key. For links, desktop first fetches ordinary HTML locally with DNS/public-address checks, pinned IP, redirect and size limits; a 403/429/503 response or recognized challenge HTML falls back to an ephemeral sandboxed Electron window that denies permissions and downloads. The fallback session has no direct network route: every HTTPS/WSS tunnel goes through an ephemeral local CONNECT proxy that validates every resolved address and connects to the selected public IP without a second hostname lookup; HTTP and private targets are rejected. Eden then extracts generic Schema.org/JSON-LD, Open Graph and labeled visible text, and uses a valid extracted ISBN to fill only missing title/author/cover/pages/language/publisher/publication-date values; source-page values always win, and an API failure does not discard them. In the confirmation preview every found field is selected by default and replaces its current title/header value through the existing `TiptapEditor` autosave path; the user can uncheck individual fields to preserve them. The Markdown body is never changed, and an old local cover is deleted only after the replacement saves successfully. This is best-effort and manual/offline editing remains fully available.
- Person pages derive display name from `first_name`, `last_name`, `patronymic`; fallback is entry title/type name.
- Person/image visual fields may reference image objects; resolve through `lib/objectImages.ts` when available.
- Type changes must update `type_id`, `header_layout`, and `header_props_json` together; avoid editor-specific divergent metadata paths.
- Direct ARK calls from components are forbidden; use Eden API/shim/store paths.
