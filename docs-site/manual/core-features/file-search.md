# Поиск файлов

Начни печатать в поисковике — Kepler покажет совпадающие файлы сразу после приложений. Нажми **Enter** или кликни, чтобы открыть файл в ассоциированной программе.

## Как это работает

При первом запуске Kepler индексирует все файлы на локальных дисках и сохраняет индекс в data-dir Kepler (`%APPDATA%\Kosmos\file-index.db` в production, `%APPDATA%\Kosmos-dev\file-index.db` в dev). Индекс обновляется в фоне — изменения в файловой системе подхватываются автоматически без перезапуска.

Результаты поиска показывают имя файла и полный путь к нему.

На локальных NTFS-дисках Kepler использует быстрый системный путь: установленный **Kepler Focus Service** читает файловую таблицу диска и отдаёт список файлов backend'у. Поэтому первый scan обычно занимает секунды, а не долгий обход папок. Если service не установлен или недоступен, Kepler автоматически вернётся к обычному обходу файловой системы.

## Что исключается

По умолчанию из индекса вырезаются «шумные» папки, которые не нужны в ежедневной работе:

- `node_modules`, `.git`
- Сборочные директории (`target`, `dist`, `build`, `out`)
- Временные и скрытые системные каталоги

Это настраивается в **Настройки → Исключать шумные папки из поиска файлов**. Переключение сразу запускает переиндексацию.

## Производительность

Первая индексация на NTFS обычно занимает несколько секунд (зависит от размера дисков). После этого поиск мгновенный — все запросы идут в локальную SQLite, не по диску. На не-NTFS, сетевых или съёмных дисках Kepler использует более медленный обычный обход.
